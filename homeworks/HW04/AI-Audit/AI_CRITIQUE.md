# AI Critique

AI helped me build the HW04 Playwright suite faster, and it did a good job with the basic structure. The tests are separated into different feature files, the test data is stored in JSON, and the suite uses several assertion styles instead of repeating the same check every time. That made the work easier to follow and gave me coverage for FR-04, FR-08, and FR-18.

The main problems showed up during human review and in the Playwright report. In FR-04, the valid profile tests use `page.once('dialog', ...)` and then check `dialogMessage` right away. The report shows that the message was still empty when the assertion ran, so the test was too dependent on timing. The shipping-address case also needs caution because the report shows the phone value `0912345678`, so that failure may be caused by bad test data or validation rules instead of an application bug. In FR-08, several checkout tests expected the page to reach `/checkout`, but the report shows the browser staying on `/login`. That means the script assumed the user was already authenticated or that navigation had already happened, but the evidence does not confirm that.

This assignment taught me that AI is useful for generating test ideas and scripts quickly, but it does not replace understanding the application itself. A failed automation test does not automatically mean the app is broken. It can also mean the test is waiting badly, using the wrong data, or assuming the wrong state. Human review was necessary to catch those problems and to decide whether the result was a real defect or just a mistake in the automation. Overall, the AI scripts were a helpful starting point, but they still needed careful checking before I could trust them.
